## 좋은 프롬프트의 구성 요소

### 1. 역할 지정 (Role)
```
시니어 백엔드 개발자처럼 이 코드를 리뷰해줘
보안 전문가 관점에서 취약점을 찾아줘
```

### 2. 맥락 제공 (Context)
```
// 나쁜 예
함수 만들어줘

// 좋은 예
Node.js + TypeScript 환경에서
PostgreSQL의 users 테이블을 조회하는 함수를 만들어줘
페이지네이션(page, limit)을 지원하고 삭제된 레코드는 제외해야 해
```

### 3. 형식 지정 (Format)
```
결과를 다음 형식으로 알려줘:
1. 문제점
2. 원인
3. 해결 방법 (코드 포함)
```

### 4. 제약 조건 (Constraints)
```
- lodash 없이 순수 JavaScript로 작성
- ES6+ 문법 사용
- 외부 라이브러리 사용 금지
- 함수형 프로그래밍 스타일로
```

## 반복 작업 자동화 패턴

### 일관된 코드 스타일 유지
주석에 패턴을 명시하면 Copilot이 동일한 스타일로 완성합니다.

```typescript
// 패턴: async 함수 → try/catch → 로깅 → 에러 래핑
async function createUser(data: CreateUserDto): Promise<User> {
    try {
        logger.info('Creating user', { email: data.email });
        const user = await userRepository.create(data);
        logger.info('User created', { userId: user.id });
        return user;
    } catch (error) {
        logger.error('Failed to create user', { error, data });
        throw new AppError('USER_CREATE_FAILED', error);
    }
}

// 위 패턴을 학습한 Copilot이 다음 함수도 같은 패턴으로 완성

    // Tab → 같은 패턴으로 자동 완성
}
```

## 단계적 접근법 (Chain of Thought)

복잡한 작업은 단계를 나눠 요청하면 더 정확합니다.

```
Step 1: 먼저 이 API의 구조를 설계해줘 (코드 없이 설명만)
Step 2: [설계 확인 후] 설계를 바탕으로 인터페이스/타입 먼저 작성해줘
Step 3: [타입 확인 후] 이 타입들을 사용해서 구현 코드 작성해줘
Step 4: [구현 확인 후] 테스트 코드 작성해줘
```
